# KMENAS — סימולטור K-Means לימודי

אתר סטטי בקובץ אחד (`index.html`) + מאגר קבצים (`data/`, `catalog.json`) — מוכן לפרסום ב-GitHub Pages ללא build, שרת, או תלות בשרת חיצוני.

## חיבור הריפו המקומי ל-GitHub

הפרויקט הזה כבר מאותחל כריפו Git מקומי (ענף `main`, עם היסטוריית קומיטים מסודרת). כדי לחבר אותו לחשבון GitHub שלכם:

1. צרו ריפו **ריק** חדש ב-GitHub בשם `KMENAS` (בלי README/gitignore/license — כדי לא להתנגש עם מה שכבר יש).
2. בטרמינל, בתוך תיקיית הפרויקט:

```bash
git remote add origin https://github.com/<username>/KMENAS.git
git push -u origin main
```

(אם אתם מעדיפים SSH: `git remote add origin git@github.com:<username>/KMENAS.git`)

3. לאחר הפוש, המשיכו לשלב "פרסום ב-GitHub Pages" למטה.

## פרסום ב-GitHub Pages

1. צרו ריפו חדש ב-GitHub והעלו את כל התוכן של התיקייה הזו (`index.html`, `catalog.json`, `data/`, `README.md`) לענף הראשי.
2. בהגדרות הריפו: **Settings → Pages → Source** בחרו את הענף (`main`) והתיקייה (`/root`), ושמרו.
3. לאחר דקה-שתיים האתר יהיה זמין בכתובת `https://<username>.github.io/<repo-name>/`.

**חשוב:** טעינת הקבצים האוטומטית (`catalog.json` + קובצי ה-CSV) מתבצעת באמצעות `fetch()`, שדורש הגשה משרת http/https אמיתי. פתיחת `index.html` ישירות מהדיסק (`file://…`) **לא תעבוד** בדפדפנים מרוב הסיבות של אבטחת CORS — לבדיקה מקומית הריצו שרת סטטי פשוט מתוך התיקייה:

```bash
python -m http.server 8000
# ואז פתחו http://localhost:8000
```

GitHub Pages עצמו מגיש הכול דרך https, כך שאין צורך בשום דבר נוסף לאחר הפרסום.

## מבנה הקבצים

```
index.html       — כל האפליקציה (HTML/CSS/JS), טוענת נתונים דרך fetch()
catalog.json      — מאגר: אילו קבצים קיימים, ואילו תרחישי לימוד מוגדרים
data/*.csv        — קובצי הנתונים בפועל (נטענים אוטומטית, לא דרך בחירת קובץ מהדיסק)
```

## הוספת תרחיש לימוד — שתי דרכים

**דרך 1: בזמן אמת, בממשק (הכי מהיר — לא דורש עריכת קבצים)**

1. הוסיפו קובץ CSV לתיקיית `data/` ודחפו (`git push`) לריפו ב-GitHub. זהו — אין צורך לערוך את `catalog.json`.
2. פתחו את מצב הגדרות מורה (`Ctrl+C` ואז `Ctrl+M`, או כפתור 🎓 בתחתית העמוד). האתר קורא ישירות מ-GitHub API את רשימת הקבצים שבאמת קיימים בתיקיית `data/` של הריפו — כולל קבצים חדשים שעוד לא רשומים ב-`catalog.json` (מסומנים ב-🆕). אם דחפתם קובץ תוך כדי שהחלון פתוח, לחצו 🔄 לרענון.
3. בטופס "יצירת תרחיש חדש": תנו שם (זה מה שיופיע בתפריט הראשי), בחרו את הקובץ מהרשימה, ובמידת הצורך הגדירו תיאור, K, ‏Min-Max וקווי מרחק. לחצו "➕ הוסף תרחיש לתפריט".
4. התרחיש מופיע מיד בתפריט "תרחישי לימוד" הראשי — עדיין רק לכם, בסשן הנוכחי בדפדפן.
5. כדי לשמר אותו (לעצמכם, לשיעור הבא, או להעביר למחשב אחר): "⭳ ייצוא קונפיגורציה" שומרת קובץ JSON עם כל התרחישים שיצרתם; "⭱ ייבוא קונפיגורציה" טוענת אותו בחזרה.

**הערה:** רשימת הקבצים החיה דורשת שהאתר רץ בפועל על `<username>.github.io/<repo>/…` (כך שהאתר יכול להסיק את שם הריפו). בבדיקה מקומית (`localhost`) או בדומיין מותאם אישית, הרשימה תיפול-חזרה אוטומטית לקבצים הרשומים ב-`catalog.json` בלבד — האפליקציה תציג הודעה על כך בפאנל. שימו לב גם ש-GitHub API הציבורי מוגבל ל-60 בקשות לשעה לכל IP ללא התחברות — מספיק בהחלט לשימוש כיתתי רגיל.

**דרך 2: קבוע, בקובץ `catalog.json`** (כדי שהתרחיש יהיה זמין לכולם בלי צורך בייבוא קונפיגורציה, ובלי תלות ב-GitHub API)

1. הוסיפו רשומה למערך `"datasets"`:

```json
{
  "id": "myNewDataset",
  "name": "השם שיוצג בתפריט הקבצים בממשק המורה",
  "desc": "תיאור קצר לתיבת ה-tooltip",
  "file": "data/my_new_dataset.csv"
}
```

2. הוסיפו רשומה למערך `"scenarios"`:

```json
{
  "id": "q2",
  "title": "שאלה 2 · הכותרת שתופיע בתפריט",
  "description": "התיאור המלא שיוצג לתלמיד מתחת לתפריט התרחישים.",
  "dataset": "myNewDataset",
  "defaultK": 3,
  "defaultMinMax": false,
  "defaultShowLines": true
}
```

- `dataset` — ה-`id` של אחד הסטים במערך `datasets`.
- `defaultK` / `defaultMinMax` / `defaultShowLines` — הפרמטרים שייטענו אוטומטית כשהתרחיש נבחר.

התרחיש יופיע אוטומטית בתפריט תחת "תרחישי לימוד מוגדרים מראש" לכל מי שפותח את האתר — אין צורך בממשק המורה בכלל בשביל זה.

## מצב הגדרות מורה

לחיצה על `Ctrl+C` ולאחריה `Ctrl+M` (או הכפתור העדין 🎓 בתחתית העמוד) פותחת פאנל שבו ניתן:
- ליצור תרחיש לימוד חדש: שם, קובץ מתוך `data/`, תיאור, K, ‏Min-Max וקווי מרחק כברירת מחדל (ראו "הוספת תרחיש לימוד" למעלה).
- להסתיר/להציג כל בקר בממשק בנפרד (מותאם לרמת הכיתה).
- להסתיר/להציג ולמחוק תרחישים קיימים (מוגדרים-מראש או שנוצרו בממשק).
- לייצא/לייבא קונפיגורציה כקובץ JSON — כולל התרחישים שנוצרו בממשק — כדי לשמור כמה הגדרות לשיעורים שונים או להעביר בין מחשבים.

הנתונים כולם נשארים בדפדפן של המשתמש בלבד — אין שרת צד-אחורי ואין שמירה מרוחקת. תרחישים שנוצרים בממשק חיים רק בסשן הדפדפן הנוכחי, אלא אם מייצאים אותם לקובץ (או מעתיקים ל-`catalog.json` לשימור קבוע).
